# Подключённые зоны СК-63

Актуально на 29.10.2026 после партии
[PUBLISHED_BATCH_2026_10_29.md](PUBLISHED_BATCH_2026_10_29.md).
Работают все **103 зональные записи каталога geoproj**, плюс сохранены
**17 исходных определений EPSG**. В интерфейсе 120 доступных пунктов и
4 района без уточнённого перечня зон. Количество пунктов не равно числу
различных проекций: часть каталожных записей является проверенными
соответствиями уже подключённых EPSG.

## Определения и проверка

Данные хранятся в `sk63_definitions.json`, загружаются `../sk63_registry.py`.
Исследовательский `geoproj_catalog.reference.json` не включает кандидатов
автоматически: только явная проверенная запись меняет статус на ready.

Ранние источники P и V сохранены: научная публикация Бурковського и соавторов
[2021, DOI](https://doi.org/10.30748/zhups.2021.70.08), каталог GeoBridge,
пособие Денисова. Для C1–C2 и X1–X6 сохранены подтверждённые соответствия EPSG.
Новая партия содержит 75 определений из
[geo-ts/sk63, фиксированная ревизия](https://github.com/geo-ts/sk63/blob/ea767b0fe5afe96bfe6fc4c8c5aff85a54112dda/index.ts)
и 10 уточнённых опубликованных вариантов I/L из
[GeoBridge](https://geobridge.ru/proj/api).

Для каждого нового определения сохранены три искусственные контрольные
пары WGS-84 → СК-63 из geoproj. Проверены оси, метры, знаки смещений,
опубликованный переход датума и обратный расчёт. Допуск согласованности — 0,01 м.

## Различия источников

- C1 каталога имеет меридиан 24,95°, а C1 старой статьи — 21,95°.
  Новые C3–C6 подключены по явным опубликованным определениям и контрольным
  парам; нумерация не перенесена из несовпадающей таблицы статьи.
- T1–T4 теперь подтверждены по GitHub/GeoBridge: меридианы 37°59′,
  40°59′, 43°59′, 46°59′. Ранние противоречивые кандидаты статьи
  остаются отклонёнными; их параметры не исправлялись догадкой.
- I1–I4 используют опубликованное GeoBridge N0=−12900,60 м.
  Вариант GitHub −12900,566 м расходится примерно на 0,034 м и не подключён.
- L1–L6 используют опубликованные точные меридианы 81°31′ + 6°*(n−1).
  Округлённые записи GitHub дают расхождение около 0,021 м и не подключены.
- V1 не является МСК-63 Самарской области или МСК-16 Татарстана:
  северные смещения отличаются на миллионы метров.
- Для X при lat_0=0 северное смещение отрицательное, примерно −9214,688 м.
  Нельзя смешивать это смещение с начальной широтой другого варианта EPSG.

## Что остаётся в разработке

Районы **B, H, U, Y**: опубликованный и проверенный перечень зон не установлен.
Четыре пункта `SK63:DISTRICT:*` отключены на фронтенде и отклоняются API.
Параметры и номера зон для них не экстраполируются по соседним районам.

## Оси и точность

В API и Excel **X — восток, Y — север** (`always_xy=True`), независимо от букв
осей первоисточника. Работают переходы между подключёнными СК, импорт 100 строк
и оба экспорта. Неподтверждённые ballpark-операции запрещены. Общий движок:
[GK.md](GK.md); МСК: [MSK.md](MSK.md).

Совпадение искусственных контрольных пар показывает согласованность формул,
не подтверждает геодезическую точность на всей территории. Официальные ключи,
искажения сетей, эпохи наблюдений и точные границы районов требуют отдельного
контроля. Новые BBOX не выводились из тестовых точек. Пользовательские
координаты не передаются внешним сервисам, тесты работают без сети.

Проверка из `backend`: `python -B -m unittest discover -s tests -v`.
