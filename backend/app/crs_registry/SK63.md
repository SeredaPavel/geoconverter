# Подключённые зоны СК-63

Рабочий реестр `app/sk63_registry.py` использует явно разрешённые EPSG и отдельный
файл проверенных каталожных определений `sk63_definitions.json`. Исследовательский
`geoproj_catalog.reference.json` не включает кандидатов автоматически.

## Определения EPSG

| Район и зоны | EPSG | Статус API |
| --- | --- | --- |
| A1–A4 | 2935–2938 | ready |
| K2–K4 | 2939–2941 | ready |
| C0–C2 | 3350–3352 | ready |
| X1–X7 | 7825–7831 | ready |

Эти 17 определений сохранены; параметры установленной базы PROJ при старте
сверяются с исследовательским JSON. Пример кода: `SK63:EPSG:7828`.

## Проверенные записи каталога geoproj на 29.10.2026

| Район и зоны | Рабочее определение | Проверка |
| --- | --- | --- |
| C1–C2 | EPSG:3351–3352 | По 3 точки WGS-84 → СК-63 |
| X1–X6 | EPSG:7825–7830 | По 3 точки WGS-84 → СК-63 |
| P1–P4 | Проекция на Pulkovo 1942 из публикации 2021 года | По 3 точки WGS-84 → СК-63 |

Коды: `SK63:GEOPROJ:C:1`, `SK63:GEOPROJ:X:4`, `SK63:GEOPROJ:P:2`.
Итого 29 доступных пунктов: 17 исходных EPSG, 8 проверенных соответствий
каталога уже имеющимся EPSG и 4 новых определения района P. Это **21 различная
проекция**, а не 29 различных зон.

Источник P: С. І. Бурковський и соавторы,
[«Впровадження системи координат СК-63 у спеціальне програмне забезпечення “Віраж”»](https://doi.org/10.30748/zhups.2021.70.08),
2021, таблица 2. Осевые меридианы P1–P4: 32°29′, 35°29′, 38°29′, 41°29′.
Восточные смещения: 1250000, 2250000, 3250000, 4250000 м. Для PROJ используется
`lat_0=0`, `y_0=-12900.563`, масштаб 1. Положительная величина сдвига в таблице
вычитается из северной координаты. Знак и нумерация проверены по geoproj;
параметры не подгонялись под контрольные точки. Расхождение менее 0.004 м,
допуск тестов — 0.01 м. Это согласованность реализаций, не оценка точности зоны.

## Оставшиеся записи

Из 103 каталожных сочетаний подключены 12, остальные 91 остаются `dev`.
Ещё 4 записи районов B, H, U, Y имеют пометку «зоны уточняются».
Таким образом, 95 пунктов СК-63 недоступны для выбора и отклоняются API.

Нумерация C в статье 2021 года отличается от подтверждённого каталога geoproj:
в статье C1 имеет меридиан 21.95°, у geoproj C1 / EPSG:3351 — 24.95°.
Старые кандидаты статьи не заменяются одноимёнными EPSG автоматически.
Для C3 и далее подтверждённых здесь определений нет.

Кандидаты T1–T4 из таблицы 2 не совпали с geoproj: расхождения порядка 375 км
на выбранных контрольных точках. Кроме того, таблицы 2 и 5 статьи содержат
разные меридианы для T. Они не подключены; параметры не исправляются догадкой.
Отклонённые проверки сохранены в `sk63_definitions.json` отдельно от `definitions`.

## Оси и точность

В API и Excel **X — восток, Y — север** (`always_xy=True`), независимо от букв
осей исходного определения. Район и зона задаются выбранной записью;
миллионный префикс не используется для автоматического выбора СК-63.

Работают переходы с географическими СК, ГК, рабочими МСК и другими СК-63.
Операции PROJ без нужных ресурсов отклоняются; `allow_ballpark=False` сохраняется.
`meta.operations` возвращает описание и заявленную точность операции,
`meta.regional_definitions` — сведения о выбранных определениях. Неизвестная
точность возвращается как `null`.

Тесты используют сохранённые контрольные пары, не обращаются в интернет и
проверяют все рабочие начала проекций, обратный пересчёт, межсистемные переходы,
блокировку dev, импорт 100 точек и оба Excel-экспорта.
Запуск из `backend`: `python -B -m unittest discover -s tests -v`.
