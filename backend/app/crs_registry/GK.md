# Гаусс–Крюгер и общий движок пересчёта

Проверено 29.10.2026. Приложение использует pyproj 3.6.1 / PROJ 9.3.0.
Реестр `gk_definitions.json` содержит явные соответствия зон и EPSG.
Коды не вычисляются сложением: например, СК-42 3°, зона 34 — EPSG:2551,
зона 60 — EPSG:3389; СК-95 3°, зона 60 — EPSG:3390.

| Семейство | Геодезическая основа | Зоны 6° | Зоны 3° |
| --- | --- | --- | --- |
| ГК-СК-42 | EPSG:4284 | 4–32 | 7–64 |
| ГК-СК-95 | EPSG:4200 | 4–32 | 7–64 |
| ГК-ГСК-2011 | EPSG:7683 | 4–32 | 7–64 |

Всего 261 определение. Прежний общий диапазон 2–33 был неверен для выбранных
семейств EPSG. Неподдерживаемая зона возвращает HTTP 400, в том числе для пустого
списка точек. Зона 3° не является зоной 6° с тем же номером.

## Источники и проверка

- [PROJ 9.3.0, projected_crs.sql](https://github.com/OSGeo/PROJ/blob/9.3.0/data/sql/projected_crs.sql)
  — определения СК-42/СК-95 3° и 6°, ГСК-2011 6°.
- [Актуальная таблица projected_crs.sql, фиксированная ревизия](https://github.com/OSGeo/PROJ/blob/5fa31c29f0a806568ed7bc76c1a557604db4a804/data/sql/projected_crs.sql)
  и [conversion.sql той же ревизии](https://github.com/OSGeo/PROJ/blob/5fa31c29f0a806568ed7bc76c1a557604db4a804/data/sql/conversion.sql)
  — опубликованные EPSG:21207–21264, ГСК-2011 / GSK 3GK zone 7–64.
  Имена, геодезическая основа, система осей EPSG:4530, метод и все пять параметров
  проверены по этим таблицам. SHA-256 исходных файлов сохранены в JSON.
- [Каталог Apache SIS](https://sis.apache.org/tables/CoordinateReferenceSystems.html)
  — дополнительная сверка наличия новых кодов ГСК-2011.
- [Описание Transverse Mercator в PROJ](https://proj.org/en/stable/operations/projections/tmerc.html)
  и [API Transformer в pyproj](https://pyproj4.github.io/pyproj/stable/api/transformer.html).

Для ГСК-2011 3° в старой установленной базе нет новых записей EPSG.
`gk_registry.py` воспроизводит их из сохранённых опубликованных параметров,
с настоящими идентификаторами EPSG проекции и операции. При наличии записи
в установленной базе она используется напрямую. Изменения глобального `proj.db`
и загрузка данных при запуске не требуются.

Параметры: широта начала 0°, масштаб 1, северное смещение 0 м.
Осевой меридиан — `6*n - 3` для зон 6°, `3*n` для зон 3°.
Восточное смещение — `n*1000000 + 500000` для СК-42/СК-95 и ГСК-2011 6°;
**для ГСК-2011 3° — `n*1000000 + 250000`**.
Поэтому трёхградусную ГСК-2011 нельзя получать простой заменой эллипсоида
в определении трёхградусной СК-42.

При создании каждой CRS код проверяет геодезическую основу, метод EPSG:9807
и пять параметров. Тесты проверяют все 261 начала проекций и обратные расчёты,
пропуски EPSG, переходы между семействами/ширинами/зонами, границы и прежние
независимые контрольные точки МСК/СК-63.

## Независимые настройки двух сторон

`GET /crs` возвращает `gk_zones`, например `{"3":[7,...,64],"6":[4,...,32]}`.
Интерфейс получает допустимые номера из этого поля. Ширина, автоматический
выбор номера и ручная зона задаются отдельно для исходной и целевой ГК.
«Реверс» меняет местами обе настройки вместе с СК и координатами.

Пример `POST /convert` для ГК-СК-42 6°, зона 7 → ГК-ГСК-2011 3°, зона 13:

```json
{
  "crs_from": "GK_SK42",
  "crs_to": "GK_GSK2011",
  "points": [{"x": 7500000, "y": 6100000}],
  "options": {
    "source_gk": {"auto_zone": false, "zone_mode": 6, "zone": 7},
    "target_gk": {"auto_zone": false, "zone_mode": 3, "zone": 13}
  }
}
```

Прежние плоские поля `options.auto_zone`, `zone_mode`, `zone` сохранены как
резервные настройки. Явный объект `source_gk` или `target_gk` полностью заменяет
их для соответствующей стороны; отсутствующие поля объекта получают обычные
значения по умолчанию. В ручном режиме номер обязателен.

В авто-режиме исходный номер берётся из миллионного префикса **X — восток**.
Ширина зоны из координат не определяется. Для целевой ГК сначала вычисляется
долгота в её геодезической основе, затем номер зоны для каждой точки.
Северо-восток России корректно обрабатывается через 180°: −177° = 183° в.д.,
зона 31 для 6° и 61 для 3°. Граница соседних зон относится к восточной зоне.

Приложение сохраняет своё соглашение **X = easting, Y = northing**, используя
`always_xy=True`. Это отличается от обычных российских геодезических обозначений
X — север, Y — восток. Полные координаты содержат миллионный префикс как в EPSG.
Ручной выбор номера не добавляет префикс к усечённой координате автоматически.

## Общие маршруты и ограничения точности

`conversion_engine.py` разрешает обе CRS и выполняет прямой переход через PROJ
для географических, ГК и подключённых МСК/СК-63 в любом сочетании.
Промежуточный WGS-84 не навязывается всем маршрутам. Применяется
`allow_ballpark=False`, ошибки и неподтверждённые зоны возвращаются как HTTP 400.
В `meta.operations` возвращаются выбранные операции и заявленная PROJ точность,
в `source_used_zones` / `target_used_zones` — номера зон каждой стороны.

`allow_ballpark=False` не означает геодезическую точность любого результата:
точность зависит от исходной реализации СК, области применения операции,
параметров локализации и доступных сеток. Например, стандартный EPSG:9773
ГСК-2011 → WGS-84 имеет нулевые смещения и заявленную точность 1 м.
Ранее опубликованные ограничения приближённой МГГТ сохраняются.

### ПЗ-90.02 / ПЗ-90.11

PROJ 9.3.0 не экспортирует EPSG-метод 1066 в исполняемый pipeline.
`reference_frames.py` явно применяет статические параметры опубликованных
операций через геоцентрические координаты:

| Операция | Переносы, м | Повороты, миллисекунды дуги | Масштаб, ppm | Опорная эпоха |
| --- | --- | --- | --- | --- |
| EPSG:7703, ПЗ-90.02 → ПЗ-90.11 | −0.373; 0.186; 0.202 | −2.3; 3.54; −4.21 | −0.008 | 2010.0 |
| EPSG:7705, ГСК-2011 → ПЗ-90.11 | 0; 0.014; −0.008 | −0.562; −0.019; 0.053 | −0.0006 | 2011.0 |

Источники: [таблица Helmert PROJ/EPSG](https://github.com/OSGeo/PROJ/blob/9.3.0/data/sql/helmert_transformation.sql),
[реализация операций PROJ](https://github.com/OSGeo/PROJ/blob/9.3.0/src/iso19111/operation/transformation.cpp),
[правила единиц и соглашений Helmert](https://proj.org/en/stable/operations/transformations/helmert.html).
Коэффициенты читаются из установленного реестра EPSG, тип метода и единицы
проверяются. Повороты переводятся из mas в угловые секунды, используется
`coordinate_frame`, обратные переходы исполняются как обратные операции.
ГСК-2011 служит связующей основой для остальных CRS. Независимый тест проверяет
знаки, единицы и порядок операций отдельным матричным расчётом.

Это **двумерный статический расчёт с исходной эллипсоидальной высотой 0 м**.
Он не учитывает эпоху наблюдений, скорости движения пунктов и не является
полноценным 4D-преобразованием между эпохами 2010 и 2011. Точность отдельных
EPSG-операций не выдаётся за точность всей такой цепочки: в итоговой операции
`accuracy_metres=null`. В метаданных указаны обе опорные эпохи,
`coordinate_epoch_modelled=false`, `assumed_input_height_metres=0`;
ограничение отображается пользователю после расчёта.
