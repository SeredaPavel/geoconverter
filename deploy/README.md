# Развёртывание GeoConverter

GeoConverter работает на общем VPS. Первоначальный перенос и настройка CI/CD
завершены. Документ описывает конфигурацию из репозитория; фактические версии
образов и установленных серверных файлов проверяются отдельно на VPS.

## Архитектура

Production использует `deploy/compose.yaml` и общий Caddy. Корневые
`docker-compose.yml` и `Caddyfile` описывают прежнюю схему размещения и не являются
конфигурацией текущего VPS.

| Компонент | Путь или значение |
| --- | --- |
| Compose приложения | `/opt/hosting/geoconverter/compose.yaml` |
| Версии образов | `/opt/hosting/geoconverter/.env` |
| Временные загрузки | `/opt/hosting-data/geoconverter/uploads` → `/app/uploads` |
| Общий edge | `/opt/hosting/edge` |
| Общий Caddyfile | `/opt/hosting/edge/conf/Caddyfile` |
| Внешняя Docker-сеть | `hosting_geoconverter_edge` |
| Backend в сети | `geoconverter-backend:8000` |
| Frontend в сети | `geoconverter-frontend:3000` |
| Серверный скрипт деплоя | `/usr/local/sbin/deploy-geoconverter` |

Порты приложений не публикуются на хост. Общий Caddy подключается к той же внешней
сети и обслуживает несколько сайтов; при изменениях нужно сохранять их настройки.
Каталог загрузок и внешняя сеть должны существовать до запуска Compose.

Frontend использует Next.js standalone со статическими файлами и шаблонами Excel.
Адрес API `/api` встраивается при сборке образа. Backend использует FastAPI и pyproj;
в Compose заданы `PROJ_NETWORK=ON`, `UPLOAD_DIR=/app/uploads` и
`UPLOAD_RETENTION_SEC=3600`. Каталог гридов с хоста поверх PROJ не монтируется.
Сетевые ресурсы PROJ зависят от доступа контейнера к внешним источникам;
для СК-63 подключены 17 определений EPSG районов A, K, C и X.
МСК и неподтверждённые варианты СК-63 остаются в разработке.

Оба сервиса имеют `restart: unless-stopped` и healthchecks. Frontend ожидает healthy
backend. Проверка backend обращается к `/api/health` и запускает очистку загрузок
старше срока хранения. Загрузки находятся вне каталога релиза.

## Маршрутизация

Фрагмент для общего Caddy находится в `deploy/geoconverter.caddy`:

- `www.geoconverter.ru` перенаправляется на `https://geoconverter.ru` с сохранением URI.
- `/api` и `/api/*` направляются в backend **с сохранением префикса `/api`**.
- Остальные пути направляются во frontend.
- `/healthz` возвращает статический ответ Caddy и проверяет только edge.

Для проверки приложения нужен `/api/health`. Не заменяйте `handle` на `handle_path`
без согласования маршрутов backend: `handle_path` удаляет совпавший префикс.

## Сборка и автоматический деплой

Workflow `.github/workflows/deploy.yml` собирает backend и frontend на GitHub
runner, запускает контейнеры и проверяет HTTP-ответы. Дополнительно проверяются
список CRS и доступность Excel-шаблона. Эти smoke-проверки не подтверждают
геодезическую точность расчётов.

| Событие | Действия |
| --- | --- |
| Push в `main` | Сборка, проверки, публикация в GHCR, автоматический деплой |
| Push в `dev` или `infra/ghcr-hosting` | Сборка, проверки, публикация без деплоя |
| Pull Request в `main` или `dev` | Сборка и проверки без публикации и деплоя |
| Ручной запуск | Сборка и публикация; деплой только из `main` с параметром `deploy=true` |

Push в `devcodex` текущим фильтром workflow не предусмотрен.
Образы публикуются с тегами конкретного коммита:

```text
путь backend: ghcr.io/seredapavel/geoconverter-backend:sha-<полный-SHA>
путь frontend: ghcr.io/seredapavel/geoconverter-frontend:sha-<полный-SHA>
```

Деплой начинается только после успеха обоих заданий сборки. Активный запуск
workflow не отменяется новым коммитом; серверная блокировка
`/run/lock/geoconverter-deploy.lock` предотвращает одновременные обновления.

GitHub Actions подключается по ограниченному SSH-ключу. Разрешены только команды
`check` и `deploy <40-символьный SHA>`. Настройка ключа, имена Actions secrets и
порядок установки описаны в [CICD.md](CICD.md). Секреты не хранятся в репозитории;
доступ VPS к GHCR настраивается отдельно в Docker-конфигурации сервера.

## Порядок обновления и откат

Скрипт `deploy/deploy-geoconverter.sh`:

1. Проверяет команду, блокировку и наличие серверных Compose и `.env`.
2. Готовит новые ссылки на оба образа одного коммита, проверяет Compose и скачивает образы.
3. Сохраняет прежний `.env` в `/opt/hosting/geoconverter/releases/`.
4. Переключает `.env` и запускает контейнеры с ожиданием healthchecks до 180 секунд.
5. Проверяет API и frontend через локальный HTTPS Caddy с проверкой сертификата.
6. При успехе сохраняет прежние настройки в `/opt/hosting/geoconverter/previous.env`.

При ошибке после переключения скрипт пытается восстановить предыдущий `.env`
и контейнеры. Неудачный откат явно отмечается в журнале и требует проверки.
Предыдущие образы нужно сохранять для возможности восстановления.

Для ручного отката сначала проверьте текущие настройки и сохраните их копию,
затем восстановите проверенные ссылки на предыдущие образы в `.env` и выполните
следующие команды в каталоге `/opt/hosting/geoconverter`.

**VPS — SSH-вкладка Termius, Bash (`root@geoconverter`):**

```bash
docker compose config --quiet
docker compose up -d --no-build --pull never --wait --wait-timeout 180
```

После обновления или отката проверьте HTTPS frontend, `/api/health`, пересчёт
контрольных координат, импорт и обе выгрузки Excel.

## Изменения серверной конфигурации

Автоматический деплой меняет только версии образов. Изменения `deploy/compose.yaml`,
`deploy/geoconverter.caddy` и серверных скриптов нужно устанавливать на VPS отдельно.
Перед этим прочитайте актуальные серверные файлы, сохраните резервные копии и
учтите остальные сайты общего VPS. Для Caddy изменяйте только блоки GeoConverter,
проверяйте конфигурацию перед перезагрузкой.

Установщик `deploy/install-actions-key.sh` сохраняет копию `authorized_keys` и
остальные ключи доступа. Его установка описана в [CICD.md](CICD.md).
Истечение срока токена GHCR требует обновления registry-доступа на VPS;
уже запущенные контейнеры при этом продолжают работать.
